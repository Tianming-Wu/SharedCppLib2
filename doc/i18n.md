## Description

`i18n` provides JSON-based translation loading with ID-based key lookup. It supports simple key→string mappings, array values with index access, and template strings with `${0}`, `${1}` placeholder substitution.

When no translation is found for a key, the key itself is returned — so you can safely use English text as keys during development.

> [!TIP]
> The recommended key format is `category.module.key` (three levels), e.g. `menu.file.open`, `ui.toolbar.save`, `dialog.confirm.title`.

## Language File Structure

Translation files are JSON files placed in a `lang/` directory relative to the executable:

```
your_app/
├── yourapp.exe
└── lang/
    ├── en-US.json
    ├── zh-CN.json
    └── ja-JP.json
```

File names follow the `lang-REGION` format (e.g. `en-US`, `zh-CN`), matching the locale codes returned by `system_locale()`.

### JSON Format

Each file is a JSON object mapping key strings to values. Two styles are supported:

**Flat style** (simple projects):

```json
{
    "menu.file.open": "Open",
    "menu.file.save": "Save",
    "dialog.confirm.title": "Confirm"
}
```

**Nested style** (recommended for larger projects):

```json
{
    "menu": {
        "file": {
            "open": "Open",
            "save": "Save"
        }
    },
    "dialog": {
        "confirm": {
            "title": "Confirm",
            "message": "Are you sure you want to delete \"${0}\"?"
        }
    },
    "app": {
        "greeting": "Hello, ${0}! You have ${1} new messages."
    },
    "ui": {
        "status": {
            "connected": ["Disconnected", "Connecting...", "Connected"]
        }
    }
}
```

Nested objects are flattened internally with `:` as the separator — `"menu":{"file":{"open":"Open"}}` becomes the key `"menu:file:open"`. Flat and nested styles can be mixed in the same file.

- **String values** — simple key→text lookup via `tr()`
- **Array values** — accessed with `trl(key, index)`, useful for status displays
- **Template strings** — `${0}`, `${1}`, etc. are replaced by arguments in `trx()`

## Quick Start

```cpp
#include <SharedCppLib2/i18n.hpp>

int main() {
    i18n t;                           // create translator (must outlive usage)
    t.autoLoad();                     // load matching system locale, or en-US fallback

    // Simple translation — xstring in, xstring out, type preserved
    auto text = i18n::tr(scl2::xstring("menu.file.open"));  // ansi → ansi

    // Array index
    auto status = i18n::trl(scl2::xstring("ui.status.connected"), 2);

    // Template with arguments
    auto msg = i18n::trx(scl2::xstring("app.greeting"), {L"Alice", 5});
    // "Hello, Alice! You have 5 new messages."
}
```

## Function Reference

### tr

```cpp
static scl2::xstring tr(const scl2::xstring& key);
```

Returns the translation for `key`. The return type matches the input key's type. If not found, returns `key` itself.

### trl

```cpp
static scl2::xstring trl(const scl2::xstring& key, size_t index);
```

Returns the value at `index` from an array translation. Return type matches the input key's type. Falls back to `key` if missing or index out of range.

### trx

```cpp
static scl2::xstring trx(const scl2::xstring& key_temp,
                         std::initializer_list<trx_arg> args);
```

Translates `key_temp`, then substitutes placeholders with the provided arguments.

**Placeholder syntax:**

| Placeholder | Behavior |
|-------------|----------|
| `${0}`, `${1}`, ... | Replaced by the argument at that index |
| `${...}` | Replaced by all arguments joined with `, ` |

Arguments can be:
- `const wchar_t*` / `const char*` / `scl2::xstring`
- `int`, `long`, `long long`, `unsigned`, `unsigned long long`
- `double`

**Example:**
```cpp
// JSON: "dialog.delete": "Delete \"${0}\"?"
auto msg = i18n::trx(L"dialog.delete", {L"config.ini"});
// "Delete \"config.ini\"?"

// JSON: "app.greeting": "Hello, ${0}! You have ${1} messages."
auto greeting = i18n::trx(L"app.greeting", {L"Alice", 5});
// "Hello, Alice! You have 5 messages."

// JSON: "ui.list": "Selected: ${...}"
auto list = i18n::trx(L"ui.list", {L"A", L"B", L"C"});
// "Selected: A, B, C"

// nullptr as placeholder — ${N} becomes empty, ${...} shows a visible gap
auto partial = i18n::trx(L"app.greeting", {nullptr, 5});
// "Hello, ! You have 5 messages."

auto list_gap = i18n::trx(L"ui.list", {L"A", nullptr, L"C"});
// "Selected: A, , C"
```

> [!NOTE]
> If fewer arguments are provided than the highest `${N}` in the template, unmatched placeholders are left as-is (not replaced with empty strings). Use `nullptr` to explicitly fill a position — `${N}` becomes empty, and in `${...}` the gap is visible as an empty entry between separators.

### trxl

```cpp
static scl2::xstring trxl(const scl2::xstring& key_temp, size_t index,
                          std::initializer_list<trx_arg> args);
```

Combines array index access with template substitution.

### system_locale

```cpp
static std::wstring system_locale();
```

Returns the system locale in `lang-REGION` format (e.g. `"en-US"`, `"zh-CN"`). Windows only; returns empty on other platforms.

### autoLoad / load

```cpp
void autoLoad();
bool load(const std::wstring& lang_code);
```

`autoLoad()` detects the system locale and calls `load()`. If detection fails, defaults to `"en-US"`.

`load()` loads `lang/{code}.json`. Returns `false` if the file doesn't exist, `true` on success.

### valid

```cpp
bool valid() const;
```

Returns `true` after a translation file has been successfully loaded.

## Key Naming Convention

Two equivalent styles:

**Flat keys** — use `.` as separator:
```
category.module.key
```

**Nested keys** — use nested JSON objects (flattened with `:` internally):
```
category:module:key
```

| Level | Purpose | Example |
|-------|---------|---------|
| category | UI area or feature group | `menu`, `dialog`, `ui`, `error` |
| module | Specific component | `file`, `edit`, `confirm`, `status` |
| key | Individual string | `open`, `save`, `title`, `message` |

Both styles produce the same lookup keys — just with different separators. Choose one and be consistent within a project.

## Notes

- The `i18n` instance must outlive all `tr()` calls. Usually created at the start of `main()`.
- Only one instance is allowed at a time (singleton). Creating a second throws `std::runtime_error` — this is the only exception the class can throw. All other error conditions (missing keys, type mismatches, missing files) degrade gracefully by returning the input key.
- Functions that return `const wchar_t*` are intentionally not provided — the returned string is a temporary that would dangle. Store the `std::wstring` result if you need `.c_str()`.
